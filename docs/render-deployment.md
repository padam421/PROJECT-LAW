# Nyay Setu: free Render deployment

The existing layout, portals and courtroom scene remain in place. The root `Dockerfile`
runs the frontend, Node API and internal Python AI in **one free web service**. Do not
deploy `frontend/` as a standalone static site: that would omit login, saved history and AI APIs.

## What free hosting can and cannot provide

- Render sleeps a free web service after 15 idle minutes; waking typically takes about a minute.
- Free web services have 750 shared instance hours per workspace per month. Your other free
  services consume the same workspace allowance. Exceeding quotas can suspend service.
- Free Render storage is temporary and SMTP ports 25/465/587 are blocked.
- Free AI and email providers impose quotas. Rate limits and outages can still happen.
- This setup is appropriate for a public demo / small pilot. It cannot meet an always-on,
  unlimited-traffic, zero-downtime production requirement. Do not describe it as having an SLA.

Sources: [Render free-service limits](https://render.com/docs/free),
[Render health checks](https://render.com/docs/health-checks).

## Aapko pehle kya ready karna hai

1. **Render access:** Connect Render in Codex, or operate your logged-in dashboard yourself.
   A screenshot confirms the account but does not grant programmatic access.
2. **External MySQL-compatible database:** For example, create a **TiDB Cloud Starter,
   MySQL-compatible** instance. Keep spending at zero, select a nearby region, and note its
   host, port, user, password and database. Do not use the MySQL server on your laptop.
   TiDB's eligible free instances currently include 5 GiB row storage and monthly request
   quotas; when those quotas are exhausted, access can be throttled or refused.
3. **HTTPS transactional email:** For example, create a Brevo account and verify the sender
   email/address or domain. Obtain its transactional API key. A Gmail SMTP app password
   does not work as an HTTPS API key. Existing SMTP settings cannot be used on free Render.
4. **Gemini API key:** Use your existing key in Render's secret environment variables.
   Check that the Google project enables the models used by this app and has quota.
5. **Google sign-in:** Set the web OAuth client ID and add the actual Render HTTPS origin
   to that client's authorized JavaScript origins in Google Cloud. Existing password
   accounts continue to use email/password; automatic linking to Google is intentionally refused.
6. **Admin:** Choose the verification-desk email and a strong new admin password.

Database reference: [TiDB Starter quotas](https://docs.pingcap.com/tidbcloud/serverless-limitations/).
Google reference: [Verify ID tokens on the server](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token).

Keep credentials in Render's environment UI / secret manager. Never paste them into
GitHub files, build commands, screenshots, URLs or chat messages.

## Render dashboard: exact settings

1. In your existing workspace, select **New → Blueprint**.
2. Connect the existing GitHub repository `padam421/PROJECT-LAW` and select `main`.
   Grant access to this repository if Render does not list it.
3. Select the root `render.yaml` and review the single `nyay-setu` service.
4. Confirm **Free**, Docker runtime and Singapore region. Do not select a paid plan.
5. Fill the requested secret values shown below, then create the Blueprint.
6. Wait for the build and `/api/ready` health check to pass. Copy the **actual** HTTPS
   `onrender.com` URL returned by Render. A repository URL or a guessed subdomain is not the live website.
7. Add that HTTPS origin to Google Cloud's OAuth client settings. If using a custom domain,
   set `APP_BASE_URL` to the canonical HTTPS URL and authorize the same Google origin.

If using **New → Web Service** instead, select this repository with Docker runtime,
leave Root Directory empty, use the root `Dockerfile`, select Free, and set health check
path `/api/ready`. Copy *all* environment values from the Blueprint.

## Data, files and retrieval

- On startup, required SQL tables are created in the configured external database.
- Accounts, sessions, lockouts, workspaces and verification records are restored from the
  remote snapshot. Successful API responses wait for that state to be saved remotely.
- Credential uploads are stored as database chunks. They survive Render restart and are
  downloaded only through the authenticated document routes. AI extraction attachments
  remain transient; their extracted text is saved in account-scoped conversation history.
- Saved citizen and advocate chats retain separate owner namespaces and optimistic revisions.
- Run **one** web instance. Snapshot writes reject competing revisions. This design is for
  a small pilot; large-scale deployment requires a transactional repository redesign.
- The package contains all **24,776** available local precedent chunks, all from the NDPS
  collection. The other four local collection databases contain zero searchable documents.
  It does not contain a million populated vectors.
- Hosted search uses SQLite FTS5/BM25 to fit the free instance. Local development keeps the
  existing Chroma vector search. Rankings can differ; embedding models are not loaded in
  the hosted profile. The source text and case metadata are preserved and checksummed.
- Regenerate the package after deliberately updating the local corpus:

  ```powershell
  python scripts/export_search_index.py
  ```

- Existing local user records and passwords are **not** published to GitHub or silently
  migrated into the new cloud database. New deployment starts with its configured admin.
  If local accounts must carry over, arrange a reviewed private database migration first.
- Take provider-side backups of both the application tables and uploaded file chunks.
  Do not assume that a free provider includes recoverable backups.

## Validation before sharing the URL

Automated checks include JS/Python regressions, actual corpus search, auth authorization,
storage outage behavior, real MySQL restart persistence, and a Linux container build/boot
with a 512 MB memory limit in GitHub CI. CI uses synthetic keys; it cannot verify your
real provider quota, sender authorization or Google Cloud OAuth origins.

After Render reports healthy, run:

```powershell
python scripts/smoke_deployment.py https://YOUR-ACTUAL-SERVICE.onrender.com
```

Then perform these checks from a second device / an incognito browser:

1. Register a real test user, receive OTP, verify it and sign out/in.
2. Open user AI chat, ask a short test question, reload and confirm the saved history.
3. Start a court hearing, submit one turn, leave and resume the same hearing.
4. Create an advocate account, complete onboarding and inspect its separate research/rehearsal.
5. Upload a synthetic PDF, restart the Render service and confirm the file still downloads.
6. Confirm another account cannot see the first account's chats or credential documents.
7. Test Google sign-in after authorizing the actual origin; test microphone/audio prompts
   interactively on the second device. Browser voices/permissions and external speech
   providers are independent dependencies, so speech availability cannot be guaranteed.
8. Verify reset-password email links use the public HTTPS hostname.

`/api/health` is liveness. `/api/ready` checks AI readiness and remote database connectivity.
Provider quota is not exercised on each health probe. Real email/AI checks above remain
necessary before announcing the site as ready.

## Fixes for common deployment failures

| Symptom | Action |
| --- | --- |
| Startup refuses SMTP configuration | Configure a verified HTTPS email API and `MAIL_FROM` |
| `ECONNREFUSED localhost:3306` | Use the cloud DB hostname and correct TLS/port settings |
| SSL/certificate error | Check host, CA and provider settings; do not disable TLS validation |
| Health check fails before Node starts | Check Gemini key presence and packaged search files |
| Saved data reports unavailable | Check external DB quotas/connectivity; do not switch to ephemeral file mode |
| AI returns 429/503 | Check actual Gemini project/model quota and retry after the stated interval |
| Google sign-in rejected | Authorize the deployed origin and use the matching web client ID |
| First visit is slow after inactivity | Expected free Render cold start; always-on behavior requires a paid plan |
| My other Render apps consume free hours | Review workspace-wide usage and plan within the shared allowance |

No payment, uptime monitor subscription, paid service or automatic billing upgrade is
created by this repository's Blueprint.
